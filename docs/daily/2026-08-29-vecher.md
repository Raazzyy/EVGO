## Что нужно сделать в терминале Replit

Полный список за оба захода 29 августа.

**1. Забрать изменения и поставить зависимости**

```bash
git pull
pnpm install
```

Зависимости обязательны: добавились `i18next`, `react-i18next`,
`expo-localization`, `expo-secure-store` и пакет лендинга.

**2. Применить миграции — порядок важен**

Первая идёт **до** `db push`: она меняет тип колонки, и drizzle-kit может
предложить пересоздать её с потерей значений.

```bash
psql "$DATABASE_URL" -f docs/sql/2026-08-29-is-promoted-boolean.sql
pnpm --filter @workspace/db run push
```

Если `push` зависнет на вопросе (ему нужен TTY) — прервите Ctrl+C и
примените остальные напрямую:

```bash
psql "$DATABASE_URL" -f docs/sql/2026-08-29-station-verification.sql
psql "$DATABASE_URL" -f docs/sql/2026-08-29-station-reports.sql
```

**3. Проверить, что всё собирается**

```bash
pnpm run typecheck
```

**4. Запустить лендинг**

```bash
PORT=5001 BASE_PATH=/ pnpm --filter @workspace/landing run dev
```

Карта покрытия берёт станции из `/api/stations`, поэтому API-сервер должен
быть запущен. Если он на другом порту — укажите его:

```bash
API_URL=http://localhost:8080 PORT=5001 BASE_PATH=/ pnpm --filter @workspace/landing run dev
```

Без API карта покажет надпись «временно недоступна» — это нормальное
поведение, а не поломка.

**5. Проверить приложение**

```bash
PORT=8080 pnpm --filter @workspace/api-server run dev
```

Что посмотреть:
- переключение языка в настройках — интерфейс меняется сразу, суммы
  показываются с правильной подписью
- внизу экрана станции — дата проверки и кнопка «Сообщить о неточности»
- в админке появился раздел «Жалобы»
- при загрузке списков теперь скелетоны, а не крутящийся индикатор
