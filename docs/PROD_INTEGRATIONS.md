# EVGO — план прод-интеграций (Payme / SMS / операторы)

Что нужно, чтобы из демо-MVP стать боевым продуктом с реальными платежами,
входом и живыми станциями. Код под всё это уже написан — не хватает договоров,
ключей и, для операторов, интеграции с их системами.

---

## 1. Payme — оплата пополнения кошелька

**Статус кода:** ✅ готово. Merchant-webhook `/api/webhooks/payme` реализован
(CheckPerformTransaction, CreateTransaction, PerformTransaction, CancelTransaction,
CheckTransaction, GetStatement), timing-safe Basic-auth, идемпотентность,
холды/возвраты. БД-констрейнты идемпотентности добавлены.

**Что нужно сделать (внешнее):**
1. Заключить договор с Payme (Paycom), получить `merchant_id` и ключ(и) кассы.
2. Добавить в Secrets: `PAYME_MERCHANT_ID`, `PAYME_MERCHANT_KEYS` (можно несколько
   через запятую), `PAYME_TEST_MODE=true` на время песочницы.
3. В кабинете Payme указать endpoint вебхука: `https://<домен>/api/webhooks/payme`.
4. Пройти **обе фазы песочницы** `test.paycom.uz` (кнопка проверки в кабинете) —
   реализация под это заточена; тесты прогоняются на реальном merchant_id.
5. Переключить `PAYME_TEST_MODE=false` → боевой приём.

**Оценка:** 1–2 дня после получения ключей (в основном — прохождение песочницы).

## 2. SMS (Eskiz) — реальные OTP при входе

**Статус кода:** ✅ готово. `sendSms()` через Eskiz, request-code/verify-code с
лимитами и хешированием кодов. Сейчас вход работает через `DEMO_PHONE`/`DEMO_CODE`.

**Что нужно сделать (внешнее):**
1. Договор с Eskiz, получить логин + секретный ключ кабинета.
2. Согласовать **шаблон SMS** (текст сейчас: `EVGO: kirish uchun kod {code}...`) —
   Eskiz модерирует тексты; отправка неодобренного шаблона не пройдёт.
3. Secrets: `ESKIZ_EMAIL`, `ESKIZ_PASSWORD` (секретный ключ, не пароль аккаунта),
   `ESKIZ_FROM` (согласованное имя отправителя), `ESKIZ_CALLBACK_URL`.
4. **Убрать `DEMO_PHONE`/`DEMO_CODE`** из Secrets после ревью в сторах.

**Оценка:** 0.5–1 день после ключей + одобрения шаблона.

## 3. Операторы (CPO) — живые данные и запуск зарядки

Это самый крупный и важный кусок. Сейчас станции — из **OpenStreetMap**
(статичный публичный слой), а запуск сессии — **симуляция**. Для боевого продукта
нужна интеграция с системами операторов (TOK BOR, Megawatt, Quwatt, K-Watt).

**Что даёт интеграция:**
- **Реальный статус коннекторов** (свободна/занята/офлайн) в реальном времени.
- **Реальный запуск/остановку зарядки** из приложения (remote start/stop).
- **Точные тарифы** и биллинг за фактические кВт·ч.

**Как правильно (стандарт индустрии — OCPI 2.2.1):**
1. С каждым оператором согласовать доступ к их **OCPI-эндпоинту** (роль EVGO = eMSP,
   оператор = CPO). Обменяться токенами (credentials).
2. Реализовать на бэкенде OCPI-клиент: модули `Locations` (станции/коннекторы),
   `Sessions`, `CDRs` (чеки), `Commands` (START/STOP), `Tariffs`.
3. Синхронизировать локации оператора в нашу БД (замена/дополнение OSM-слоя),
   подписаться на push-обновления статусов.
4. Связать запуск сессии в приложении → OCPI `START_SESSION` → холд в кошельке →
   по `CDR` списать фактическую сумму (capture холда).

**Если у оператора нет OCPI:** промежуточный вариант — их приватный API или ручной
импорт адресов/тарифов (как сейчас OSM), но без live-статуса и remote start.

**Оценка:** 1–3 недели на первого оператора (каркас OCPI), дальше по 3–5 дней на
каждого следующего. Требует технического контакта со стороны оператора.

---

## Порядок запуска (рекомендация)
1. **SMS + Payme** — быстро (дни), закрывают вход и оплату → уже можно брать
   реальные пополнения.
2. **Первый оператор по OCPI** (пилот, напр. TOK BOR) — live-статус + remote start
   на его станциях → полноценный сквозной сценарий «нашёл → забронировал → зарядил → списалось».
3. Масштабирование на остальных операторов.

## Параллельно (не блокирует, но нужно к релизу)
- Домен `evgo.uz` → Vercel/Cloudflare (лендинг) + прод-домен API.
- Реальные контакты/соцсети вместо placeholder'ов (телефон, email, Telegram, IG).
- Перевод `stations.price_per_kwh` / `sessions.cost` с `real` на `bigint` тийины
  (как в кошельке) — точность денег.
- Сузить CORS до боевых доменов.
- App Store / Google Play: `app.json` (bundle id), `eas build`, демо-доступ для ревью.
